# Phase 5 — Suivi CI

**Agent :** l'implémenteur du ticket (Luna/max ou Terra/high).
**Sortie :** PR prête à merger ou blocage qualifié.

## Boucle

1. Attends les checks avec `gh pr checks <PR> --watch`, puis classe les échecs.
2. Reproduis et corrige tout job déterministe rouge dans le worktree, sans
   assouplir la CI ni les tests.
3. Si Claude passe, n'active pas le fallback. Si Claude bloque avec des
   findings, corrige-les : le fallback ne les contourne jamais.
4. Si Claude échoue sans review exploitable (quota, auth ou panne), capture le
   SHA, publie `pending`, lance Sol/high en lecture seule, puis publie son
   verdict pour ce même SHA :

   ```bash
   review_sha="$(gh pr view <PR> --json headRefOid --jq .headRefOid)"
   bash .codex/scripts/publish-review-status.sh <PR> pending "$review_sha"
   bash .codex/scripts/publish-review-status.sh <PR> pass|block "$review_sha" "<résumé>"
   ```

5. Une review `block` revient à l'implémenteur. Pousse puis recommence. Après
   deux tours automatiques, ferme et redécoupe la PR.
6. Tier/1 et tier/2 gardent l'auto-merge. Tier/3 attend Sol/high et l'accord
   humain. Vérifie ensuite la clôture Linear.

## Garanties

- `codex-review` est un verdict fournisseur, pas le check requis. TRA-53 ajoute
  l'unique `review-gate` qui arbitre Claude ou Codex sur le même SHA.
- Codex Desktop consomme le quota ChatGPT Pro ; GitHub n'appelle aucun modèle
  OpenAI.
- Ne modifie jamais `ai-review.yml`, `claude.yml`, les modèles, secrets,
  déclencheurs ou commentaires Claude.

## Rendre

Retourne l'URL, les checks, les corrections, les tours de review et l'état du
merge ou l'unique action humaine restante.
