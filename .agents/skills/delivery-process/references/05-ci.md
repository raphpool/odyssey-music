# Phase 5 — Suivi CI

**Agent :** l'implémenteur du ticket (Luna/max ou Terra/high).
**Sortie :** PR prête à merger ou blocage qualifié.
## Boucle

1. Attends les checks avec `gh pr checks <PR> --watch`, puis classe les échecs.
2. Un job déterministe rouge (`typecheck`, `lint`, `test`, `diff-size`,
   `tier-guard`) se reproduit et se corrige dans le worktree, sans assouplir CI
   ni les tests.
3. Si Claude passe, `review-gate.yml` publie automatiquement `review-gate`.
4. Si Claude bloque avec des findings, corrige-les : le fallback ne les
   contourne jamais. S'il échoue sans review exploitable (quota, auth ou panne),
   capture le SHA, publie `pending`, lance Sol/high en lecture seule, puis
   publie son verdict pour ce même SHA :

   ```bash
   review_sha="$(gh pr view <PR> --json headRefOid --jq .headRefOid)"
   bash .codex/scripts/publish-review-status.sh <PR> pending "$review_sha"
   bash .codex/scripts/publish-review-status.sh <PR> pass|block "$review_sha" "<résumé>"
   ```

5. Une review `block` revient à l'implémenteur. Pousse puis recommence. Après
   deux tours automatiques, redécoupe la PR.
6. Tier/1 et tier/2 gardent l'auto-merge. Tier/3 attend la review profonde
   Sol/high et l'accord humain. Vérifie ensuite la clôture Linear.

## Garanties
- Codex Desktop consomme le quota ChatGPT Pro ; GitHub ne fait aucun appel à
  un modèle côté OpenAI.
- `review-gate` est le gate commun : succès Claude relayé, ou verdict Codex
  publié avec l'accès GitHub local de Raphael.
- Le profil est additif : ne modifie jamais `ai-review.yml`, `claude.yml`, les
  modèles, secrets, déclencheurs ou commentaires Claude.
- N'active `review-gate` dans la protection de `main` qu'après avoir observé le
  relais Claude vert sur une PR.

## Rendre

Retourne l'URL, les checks, les corrections, les tours de review et l'état du
merge ou l'unique action humaine restante.
